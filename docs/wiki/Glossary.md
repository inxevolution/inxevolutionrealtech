# Glossary

| Term | Meaning |
|---|---|
| ADR | Architecture Decision Record: rationale and consequences of a significant technical decision |
| API | Application Programming Interface |
| Business line | Activity area with its own owner, scope, costs, risks and measures |
| CI/CD | Continuous Integration / Continuous Delivery or Deployment |
| CRM | Customer Relationship Management |
| E2E | End-to-end testing of a complete user journey |
| GDPR | General Data Protection Regulation |
| KPI | Key Performance Indicator |
| MVP | Minimum Viable Product: smallest testable offer that validates a key assumption |
| MoSCoW | Must, Should, Could, Won't prioritisation method |
| RACI | Responsible, Accountable, Consulted, Informed |
| RPO | Recovery Point Objective: acceptable data loss measured in time |
| RTO | Recovery Time Objective: target service restoration time |
| Source of truth | Authoritative system or record for a data item |
| Stakeholder | Person or organisation that can affect or is affected by the project |
| Unit economics | Revenue and variable cost analysis at unit/customer/order level |
| Unlicense | Public-domain dedication used by the repository's current LICENSE |

Add project-specific terms only when defined and consistently used.
