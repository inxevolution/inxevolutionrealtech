# Architecture Decisions

Architecture Decision Records (ADRs) explain significant technical choices and their consequences.

## ADR index

| ID | Title | Status |
|---|---|---|
| ADR-0001 | Documentation-first project foundation | Proposed |

## When to create an ADR

Create an ADR for choices that materially affect security, data, cost, scalability, portability, team workflow or architecture. Examples include programming language, database, cloud provider, identity model, integration pattern and repository licence/visibility.

## ADR template

- ID, title, date, status and decision owner.
- Context and evidence.
- Decision drivers.
- Options considered.
- Decision and rationale.
- Consequences, risks and reversibility.
- Revisit conditions.

A preference is not an accepted decision until the authorised owner approves it.
